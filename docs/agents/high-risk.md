# 高风险改动范围

本文是「高风险改动」的唯一定义。`writing-plans`、`executing-plans`、`pr-ready` 用它决定是否必须做
**讲回（explain-back）**与**模拟飞行**；其他文档引用本文，不另写清单。

## 判定

改动只要满足下面任一条，就是高风险：

1. 落在本项目的高风险模块或功能里：

   {{HIGH_RISK_DOMAINS}}
   <!-- 按项目改写为列表，每行一个模块/功能 + 判定依据，例如：
   - 支付与订单履约（`apps/api/billing/**`）：回调重复、金额错误不可逆
   - 订阅与权益（`apps/api/entitlements/**`）：权益错发、配额记账
   - 权限与脱敏（`apps/api/auth/**`）
   - 通知投递（`apps/worker/notify/**`）：重复/漏发
   - 定时任务与调度（`apps/worker/scheduler/**`）：重叠运行
   - 数据迁移与回填（`migrations/**`）
   - 交易执行
   -->

2. 不论模块，改动包含下列任一项：
   - 不可逆操作（删除数据、对外发送、扣款）
   - 状态机新增状态或转移
   - 权限、认证或脱敏判断的变更
   - 已发布对外契约的不兼容变更（`RULES.md` §3）
   - schema 迁移、数据回填或修正（`RULES.md` §4.1、§8）

判断不清时按高风险处理，并在计划 §0 写明理由。

## 与其他配置的关系

- `skills/pr-lessons/scripts/high-risk.json` 是本文范围在**路径级**的投影，供合并后复盘打标。
  改本文的模块清单时同步改它的路径；两者冲突时以本文为准。
- `RULES.md` §8 规定的是哪些改动必须加 API / 集成测试，不是高风险判定；那份领域清单与本文
  第 2 条和模块清单应保持一致。
- `writing-plans` 的有状态领域清单（`{{PROJECT_STATEFUL_DOMAINS}}`）决定哪些计划必须画状态机，
  与本文范围通常重叠，但不是同一个判定。
